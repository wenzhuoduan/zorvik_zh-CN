设想移动端团队这周必须做出**订单历史**页面，而后端团队下个月才能做完 `/orders` 接口。等一个月显然不行，于是他们对着一个 **Mock** 开发。

**Mock API**（或*模拟服务器*）是一台小小的替身服务器，它按真接口将来作答的方式回应：同样的路径、同样的状态码、同样形状的 JSON。它背后没有数据库，也没有业务逻辑，只是把你准备好的答案返回出去。你可能还会听到 *stub* 或 *fake* 这些说法，本课程里它们是一个意思。

```sequence
participants: App, Mock, 真接口
App -> Mock: GET /orders
Mock --> App: 200 OK [{"id": 1, "total": 18.5}]
Note over 真接口: 还在开发中
```

> [!note] 可以这样想……
> 一个电影片场。从镜头这一侧看，那条街很真实：橱窗、门、招牌都有。但推开一扇门，后面什么都没有。Mock 也一样：从 App 这一侧看它就是真接口，而 App 需要的也只有这些。

## 团队为什么要 Mock

1. **前端不必等后端。** 两个团队对接口的形状（*契约*，通常写成 OpenAPI 文档）达成一致那天，双方就能同时开工。App 对 Mock 说话，后端并行开发。
2. **安全地测失败。** 服务器很慢、回 `503 Service Unavailable`、或者直接断连时，你的 App 会怎样？用真服务器你得先把它弄坏才知道。Mock 按命令出毛病，而且只对你一个人。
3. **稳定又快的测试。** 调别人家的服务（支付、地图、邮件）的测试，只要对方那天不顺就失败。你自己电脑上的 Mock 每次都一样，几毫秒就答完。
4. **演示和离线工作。** Mock 在你笔记本的 `127.0.0.1` 上跑。不需要 Wi-Fi、不需要 VPN、也不需要测试账号。

## 把 Mock 换成真家伙

你的请求用 `{{baseUrl}}` 这样的变量表示服务器地址。今天它指向 Mock；下个月你改这一个值，同一批请求就发给真接口了。

```flow
App -[今天]-> Mock API
App -[下个月]-> 真接口
```

## Zorvik 里的 Mock

Mock 放在左侧栏的 **服务器** 里。一个 Mock 就是一串**路由**：「当 `GET /orders` 进来时，用这个正文回 `200`」。这一单元你会：

- 手工搭一个 Mock，一条路由一条路由地加；
- 用 `{{request.params.id}}` 这类模板让答案动起来；
- 加上延迟、错误、断开连接，以及给浏览器 App 用的 CORS；
- 从 OpenAPI 文档或一文件夹已保存的请求生成整个 Mock。

Mock 和请求一样以纯文本文件保存在工作区里，所以整个团队跑的是完全同一个。

> [!warning] Mock 会漂移
> Mock 只知道你告诉它的。如果真接口改了而 Mock 没改，App 对着 Mock 一切正常，到了生产就崩。尽量让 Mock 贴着契约：从 OpenAPI 文档生成它，并用同一份文档校验真接口（结业项目里会演示）。

**什么时候用得上：** 后端还没好、合作方的测试环境又挂了，或者有人问「支付超时的时候 App 会怎样」而你想两分钟而不是两天给出答案。
