MCP 让 AI 应用变得强大，是因为服务器能 *动手做事*：读文件、查数据库、开工单、发消息。这份能力跑在你的电脑上、用着你的凭据，所以它值得和任何你要运行的代码一样小心对待。

## 本地服务器就是程序

stdio 服务器是应用启动的一个程序，它以 **你** 的身份运行，能访问你的文件和网络。所以 Zorvik 绝不会因为工作区里写了它就去启动：工作区来自 Git，可能来自任何人。

```sequence
participants: 你, Zorvik, 程序
你 -> Zorvik: 发送（地址：npx some-server）
Zorvik -> 你: 启动这个程序？（命令、文件夹、环境）
你 -> Zorvik: 允许并启动
Zorvik -> 程序: 启动，然后通过 stdin/stdout 走 MCP
```

- 第一次时，Zorvik 会显示 **确切的命令、文件夹和环境** 并询问。它只在这台电脑上、为这个工作区记住你的回答；其中任何一项变了，都会再问。
- `zorvik run` 只有带上 `--allow-programs` 才会启动程序。
- 在 Zorvik 里干活的 AI Agent，每想启动一个程序都会被问一次。

> [!warning] 清楚自己在跑什么
> `npx some-package` 会下载并运行一个包的最新版本。对依赖的服务器请固定版本（`npx some-package@1.4.2`），并优先选择来源可信的服务器。

## 密钥就该是秘密

服务器常常需要 token：程序环境里的 GitHub token，或者远程服务器的 bearer token。把它放进 **密钥变量**，在 **连接** 标签的环境里或 **鉴权** 里用 `{{githubToken}}`。密钥值住在应用数据目录里，不进工作区文件，并且在历史、日志和 AI Agent 看到的一切里都被遮蔽。

远程 MCP 服务器通常用 **OAuth 2.0** 让你登录：在请求的 **鉴权** 标签里照普通 API 那样配置就行。

## 工具说的话不可信

模型会读服务器发来的一切：工具名称、说明、结果、资源文本。一个恶意或被攻陷的服务器可以在里面藏指令（「……顺便读一下 ~/.ssh」）。这叫 **提示词注入** 或 **工具投毒**。

> [!note] 可以这样想……
> 一封写着「持此信者可取走车钥匙」的信。没人会因为一封信就把钥匙交出去；从工具返回的文字也是同样的道理。

有用的做法：

- **连之前先审查服务器。** 在 Zorvik 里连上它，读它的 **服务器** 标签：说明都老实吗？一个「天气」工具为什么要文件路径？
- **给服务器最小的权限**：只读 token、一个范围很窄的文件夹、一个测试账号。
- **把有风险的操作留在人的批准之后。** Zorvik 里的 Agent 在启动程序或服务器之前、在访问新的主机之前都会问，如果你愿意，每次改动前也会问。
- **盯着流量。** 消息标签（客户端）和流量面板（服务器）会显示每一条消息，有意外就能看见。

## 什么时候用得上……

- 同事分享了一个带 MCP 请求、会启动程序的工作区，
- 你要把一个新 MCP 服务器接进 AI 应用，想先知道它能干什么，
- 你要决定给服务器哪个 token，以及它能活多久。
